# RoboDistro Agent Instructions

## Purpose
This agent manages and extends the RoboDistro browser-based management console for high-performance media distribution using RDMA/SMB Multichannel and RoboCopy.

## Project Structure
- Frontend: Electron + React UI (src/)
- Backend: Node.js + Express server (server/)
- RoboCopy Integration: Subprocess calls to RoboCopy with real-time output streaming

## Key Features to Maintain/Implement

Use the numbered priority groups below as the decision hierarchy when requirements conflict. Higher-priority items take precedence; within a priority group, apply all requirements equally.

### Priority 1: Core Performance & Reliability
**Precedence: Optimize for performance on the happy path. Error handling is always required for failures, user-facing operations, and any scenario that could result in data loss or silent corruption.**

1. **Live File Tree Diff**
   - Use RoboCopy with /L for dry-run diff
   - Support /MON:1 /MOT:1 for continuous monitoring  
   - Parse /V /FP output for browser tree view
   - /UNILOG+:<filename.log> for detailed logging and live parsing to update UI in real-time
2. **Optimized RoboCopy Flags**
   - Use /MIR /E /Z /MT:32 /J /R:0 /W:0 /TBD /NP for best performance and throughput
3. **Concurrent Execution**
   - Backend must support multiple simultaneous robocopy jobs
   - Each job streams output to the browser in real-time
4. **Performance Monitoring**
   - Implement logging and monitoring to track performance metrics and identify bottlenecks in the file transfer process
5. **Error Handling & Resilience**
   - Robust handling of network blips and RoboCopy errors
   - Retry transient errors up to 3 times with exponential backoff (1 s, 2 s, 4 s); after exhausting retries, mark the job as failed and notify the user with the error details

### Priority 2: Security & User Experience
6. **Security & Access Control**
   - Ensure secure handling of network paths and credentials
   - Consider future implementation of authentication for UI access
7. **User Feedback & Status**
   - Clear UI indicators for file states (new, extra, updated)
   - Real-time status updates and error notifications in the UI
8. **User Experience**
   - Design the UI for ease of use, with intuitive controls and clear feedback on actions taken by the user

### Priority 3: Core Functionality
9. **Sync Groups & Profiles**
   - Allow logical grouping of targets
   - Support /XF and /XD for exclusions
10. **Sync group management**
   - Allow users to create, edit, and delete sync groups and profiles through the UI, with corresponding backend support for managing these configurations
   - Validate all sync group configurations on creation/edit; if invalid, display an error message specifying the issue and suggest corrective actions
   - Implement a mechanism for users to easily switch between different sync profiles and groups, with real-time updates to the UI reflecting the current active configuration
   - Handle [Disguise Designer content management guidelines](disguise-content-management.md):
     - **Version Control**: Track and manage file versioning with semantic versioning (e.g., v1.0, v2.1)
     - **Proxy Files**: Support proxy file management for preview and pre-production workflows
     - **Frame Replacement**: Enable targeted replacement of frames within sequences without full re-sync
     - **File Naming Validation**: Implement pre-distribution validation tooling to enforce naming conventions and prevent silent Designer failures
   - Accommodate version and proxy profiles for individual clients or entire sync groups at a per directory level, allowing flexible management of content versions and proxies in line with Disguise Designer best practices.
11. **Live-Ready Narrowing**
   - UI toggle to inject stricter exclusions as needed
12. **Session Management**
   - Implement session management to allow users to save and resume their sync configurations and job statuses

### Priority 4: Scalability, Quality & Extensibility
13. **Scalability**
   - Design the system to handle large file sets and high-speed transfers without performance degradation
14. **Testing**
   - Implement comprehensive testing for both backend and frontend components to ensure reliability and robustness of the system
15. **Extensibility**
   - Codebase should be modular to allow for future enhancements and additional sync strategies
16. **Documentation**
   - Maintain clear documentation for both the codebase and user-facing features to facilitate onboarding and troubleshooting

## Implementation Guidelines
- All RoboCopy invocations must be subprocesses, never blocking the node server
- If a RoboCopy subprocess fails, log the error and notify the user in the UI with status details and remediation hints
- If a RoboCopy subprocess hangs or fails to terminate, forcefully terminate it after a configurable timeout and notify the user with an appropriate error message
- Robocopy output must be streamed to the browser (consider WebSockets or chunked HTTP)
- UI must visually indicate file states (new, extra, updated, etc.)
- All network paths must use UNC format and target high-speed VLANs; validate that each UNC path is reachable before launching a RoboCopy job, and surface a descriptive error in the UI if the path is inaccessible or malformed
- Code must be robust to network blips (minimal retries, fast failover)
- Preview of robocopy commands should be available in the UI before execution, with clear explanations of what each flag does
